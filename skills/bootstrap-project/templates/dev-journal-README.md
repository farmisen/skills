# Dev journal

Implementation progress, decisions, failures, and follow-ups — concise, but detailed
enough for post-mortems and handoffs.

**Layout:** one file per month, `YYYY-MM.md`, newest entry first. Update the current
month's file for each completed work item; create the file when the month starts.

## Entry format

```markdown
## YYYY-MM-DD

**Work Items:** `<ticket/plan item>`

**Summary**
- What changed

**Decisions**
- Important choices made, and why

**Failures / Issues**
- What went wrong, was deferred, or remains uncertain

**Follow-ups**
- Concrete next steps or open questions
```
